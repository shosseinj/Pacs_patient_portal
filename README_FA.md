# سامانهٔ PACS و پرتال تصاویر بیمار

این بسته، نسخهٔ مستقل یک مرکز است: اپراتور فایل DICOM یا ZIP را بارگذاری می‌کند، پردازش در پس‌زمینه انجام می‌شود، انتساب بیمار بررسی می‌شود و پس از تأیید، بیمار تصاویر خودش را در OHIF می‌بیند. آرشیو Orthanc، پایگاه داده و فایل‌ها روی سرور خود شما هستند.

کد سایت فعلی در اختیار این پروژه نبوده است؛ بنابراین ورود یکپارچه یا اتصال به پرونده‌های سایت فعلی انجام نشده. می‌توانید فعلاً سامانه را روی زیردامنه‌ای مثل `pacs.example.com` نصب و از سایت به آن لینک بدهید. انتقال رمز بیمار در URL یا iframe سایت با حساب مشترک مجاز نیست؛ راه اتصال حساب‌ها در `docs/INTEGRATION_FA.md` آمده است.

## محتویات بسته

| مسیر | کاربرد |
|---|---|
| `portal/` | بک‌اند، کنترل دسترسی، صفحات فارسی و پردازشگر |
| `deploy/` | تنظیمات Nginx و OHIF و ایجاد دیتابیس آرشیو |
| `compose.yaml` و `compose.production.yaml` | نصب محلی و نصب HTTPS |
| `scripts/` | تنظیم اولیه، مدیریت حساب، پشتیبان و بازیابی |
| `run.sh` | اجرای خودکار محیط توسعه بدون Docker و آزاد کردن پورت‌های لازم |
| `tests/` | تست‌های خودکار و تست واقعی مرورگر |
| `examples/synthetic/` | تصاویر کاملاً مصنوعی برای تمرین |
| `docs/TEST_REPORT_FA.md` | نتیجهٔ واقعی تست‌های این تحویل و محدودیت‌ها |
| `docs/OPERATIONS_FA.md` | مدیریت سرور، ظرفیت و بازیابی |

همهٔ فایل‌های اختصاصی پروژه در ZIP هستند. Docker imageها و کتابخانه‌های عمومی با اینترنت در نصب اول دریافت می‌شوند؛ فایل‌های بیمار، رمز واقعی، دیتابیس و محیط مجازی در ZIP قرار ندارند.

## اجرای خودکار در محیط توسعه

برای اجرای همین پروژه به‌صورت محلی، از پوشهٔ پروژه دستور زیر را اجرا کنید:

```bash
bash run.sh
```

اجرای اسکریپت با مسیر کامل از پوشه‌های دیگر نیز ممکن است:

```bash
bash /home/newuser/Videos/pacs_patient_portal/run.sh
```

این دستور پرتال FastAPI، پردازشگر پس‌زمینه، آرشیو Orthanc، نمایشگر OHIF و Nginx را در پس‌زمینه اجرا می‌کند. آدرس ورود: **http://127.0.0.1:8080/portal**.

- محیط مجازی Python در `~/video/.venv/` ساخته یا دوباره استفاده می‌شود. بسته‌های Python فقط داخل همین محیط نصب می‌شوند. مسیر دلخواه را می‌توانید با `PACS_VENV=/path/to/.venv bash run.sh` تعیین کنید.
- اگر فایل‌های سرویس‌های محلی موجود نباشند، بسته‌های Orthanc و Nginx و فایل‌های OHIF دانلود و در `data/runtime/` استخراج می‌شوند؛ نصب سیستمی و دسترسی Docker لازم نیست. دریافت اولیهٔ سرویس‌ها برای **Ubuntu 26.04، معماری x86_64** آماده شده است و به اینترنت و دستورهای `apt`، `dpkg-deb`، `ldd`، `ss`، `flock` و Python 3.12 یا جدیدتر همراه پشتیبانی `venv` نیاز دارد.
- قبل از اجرا، سرویس‌های قبلی همین پروژه متوقف می‌شوند. اگر پورت‌های **8000، 8042، 8080 یا 8081** اشغال باشند، اسکریپت فرآیندهای شنوندهٔ آن‌ها را ابتدا با `SIGTERM` و در صورت لزوم با `SIGKILL` می‌بندد. فرآیندهای روی این چهار پورت، حتی اگر متعلق به پروژهٔ دیگری باشند، متوقف می‌شوند؛ پورت‌های دیگر دست‌نخورده می‌مانند. اگر حساب فعلی اجازهٔ توقف نداشته باشد، اسکریپت با پیام خطا متوقف می‌شود.
- اجرای دوبارهٔ همین دستور سرویس‌ها را راه‌اندازی مجدد می‌کند و دیتابیس، حساب‌ها و تصاویر قبلی را نگه می‌دارد. دیتابیس توسعه SQLite است؛ فایل‌های آرشیو، تنظیمات تولیدشده و لاگ‌ها زیر `data/` قرار دارند. لاگ سرویس‌ها در `data/runtime/*.log` و لاگ Nginx در `data/runtime/nginx/` است.

در اجرای تازه، اگر `.env` وجود نداشته باشد، تنظیمات توسعهٔ محلی ساخته می‌شود. برای دیتابیس خالی، حساب توسعهٔ **`admin`** با گذرواژهٔ **`Asd@12345`** ایجاد و اطلاعات آن در `data/local-admin.txt` نوشته می‌شود؛ نام کاربری و گذرواژه در صفحهٔ ورود توسعه نمایش داده و از پیش پر می‌شوند. حساب‌ها و گذرواژه‌های دیتابیس موجود تغییر نمی‌کنند. برای غیرفعال کردن نمایش اطلاعات ورود، `DEV_LOGIN_USERNAME` و `DEV_LOGIN_PASSWORD` را در `.env` خالی کرده و اسکریپت را دوباره اجرا کنید.

این روش برای توسعهٔ محلی با HTTP و آدرس loopback است. اگر `.env` برای PostgreSQL، دامنهٔ عمومی یا HTTPS تنظیم شده باشد، اسکریپت محلی آن را جایگزین نمی‌کند و قبل از توقف سرویس‌ها خطا می‌دهد. برای استقرار با Docker، از یک کپی جداگانهٔ پروژه و دستورهای بخش بعد استفاده کنید.

## پیش‌نیاز و میزبانی با Docker

یک VPS یا سرور اختصاصی Linux با Docker و Docker Compose نسخهٔ **۲٫۲۴٫۴ یا بالاتر** و Python 3 برای ایجاد تنظیمات لازم است. هاست اشتراکی PHP معمولاً برای این سرویس مناسب نیست. برای پایلوت کم‌حجم، ۴ هسته و ۸ تا ۱۶ گیگابایت RAM نقطهٔ شروع است؛ فضای تصاویر، پشتیبان مستقل و ظرفیت رشد را جدا حساب کنید. این عدد ظرفیت قطعی را تعیین نمی‌کند.

## اجرای آزمایشی روی سرور خودتان با Docker

از پوشهٔ همین بسته اجرا کنید:

```bash
python3 scripts/configure.py
bash scripts/start.sh
docker compose exec portal python -m scripts.manage create-admin --username admin
```

در روش Docker گذرواژهٔ مدیر را در ترمینال وارد کنید؛ حساب یا گذرواژهٔ پیش‌فرض وجود ندارد. صفحهٔ ورود در `http://127.0.0.1:8080/portal` است. اگر سرور دور است، با تونل SSH باز کنید:

```bash
ssh -L 8080:127.0.0.1:8080 USER@SERVER
```

۱. مدیر وارد شود و در بخش مدیریت حساب اپراتور بسازد.
۲. اپراتور بیمار را ثبت کند؛ نام کاربری و گذرواژهٔ اختصاصی بیمار را از مسیر امن تحویل بدهد.
۳. برای نمونهٔ مصنوعی، Patient ID برابر `DEMO001` و Issuer برابر `DEMO` ثبت شود.
۴. فایل `examples/synthetic/demo-study.zip` آپلود شود.
۵. پس از پردازش، نام و شناسهٔ فایل با پرونده بررسی و دکمهٔ «تأیید و نمایش به بیمار» زده شود.
۶. بیمار با حساب خودش وارد و «مشاهدهٔ تصاویر» را باز کند.

اختلاف یا نبود Patient ID، تأیید مدیر همراه علت ثبت‌شده می‌خواهد. ZIP باید فقط تصاویر DICOM همان بیمار را داشته باشد؛ DICOMDIR نادیده گرفته می‌شود. بستهٔ چند بیمار، فایل خراب و تصویر دارای SOP UID تکراری با محتوای متفاوت رد می‌شوند. اضافه شدن تصاویر تازه به مطالعهٔ منتشرشده، آن‌ها را خودکار منتشر نمی‌کند.

## نصب عمومی با HTTPS

ابتدا دامنه به سرور اشاره کند و گواهی معتبر آن دامنه آماده باشد. در نصب تازه:

```bash
python3 scripts/configure.py --url https://pacs.example.com
mkdir -p deploy/tls
# fullchain.pem و privkey.pem معتبر دامنه را اینجا قرار دهید.
bash scripts/start.sh
docker compose -f compose.yaml -f compose.production.yaml exec portal \
  python -m scripts.manage create-admin --username admin
```

در این حالت فقط درگاه ۴۴۳ سرویس عمومی است. پورت‌های دیتابیس، آرشیو، بک‌اند و OHIF منتشر نمی‌شوند. تمدید گواهی و راه‌اندازی مجدد gateway بر عهدهٔ مدیر سرور است. اگر `.env` از قبل دارید، دوباره configure اجرا نکنید؛ `PUBLIC_URL`، `PUBLIC_HOST` و `SECURE_COOKIES=true` را مطابق دامنه تنظیم کنید و رمزها را حفظ کنید.

## تست سورس

Python 3.12 و محیط مستقل:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.lock
.venv/bin/pytest -q
.venv/bin/ruff check portal scripts tests
```

تست‌ها دیتابیس و فایل موقت می‌سازند و به اطلاعات واقعی مرکز دست نمی‌زنند. شرح تست مرورگر و محیط آزمون واقعی در گزارش تست است.

## مدیریت

```bash
docker compose exec portal python -m scripts.manage reset-password --username USERNAME
docker compose exec portal python -m scripts.manage disable --username USERNAME
docker compose logs --tail 100 worker
```

در نصب HTTPS، دو `-f` مطابق دستور بالا اضافه کنید. تغییر گذرواژه و غیرفعال‌سازی تمام نشست‌های قبلی آن حساب را باطل می‌کند. مطالعهٔ منتشرشده از مسیر پنل حذف یا منتقل نمی‌شود؛ تغییر انتساب دادهٔ پزشکی نیازمند فرآیند جداگانه است.

بسته برای مشاهده و پایلوت آماده شده است. نمایش تشخیصی، تطبیق با خروجی دستگاه‌های واقعی مرکز، آزمون بار روی ظرفیت موردنظر و نصب روی سرور نهایی هنوز باید در محیط شما بررسی شوند. جزئیات تست‌شده و تست‌نشده در گزارش همراه ZIP درج شده است.
