# اتصال به سایت موجود

روش آمادهٔ این بسته، نصب روی زیردامنه و لینک «تصاویر من» از سایت به `/portal` است. قالب فارسی را می‌توانید در `portal/templates` و `portal/static` با نشان و رنگ مرکز تغییر دهید.

برای یک ورود مشترک، باید فناوری سایت و روش احراز هویت آن مشخص باشد. مسیر مناسب، OIDC/SAML یا یک تبادل کد کوتاه‌عمر در سمت سرور است؛ پرتال باید هویت معتبر سایت را به `Patient.user_id` نگاشت کند. نام بیمار یا شمارهٔ موبایل به‌تنهایی برای دسترسی کافی نیست. API عمومی ساخت لینک بیمار یا توکن در URL در این بسته وجود ندارد.

اگر برنامه زیر مسیر همان دامنه نصب شود، سه مسیر `/portal`، `/api` و `/dicom-web` باید به پرتال برسند و دارایی‌های OHIF در ریشهٔ مبدا نمایشگر سرو شوند. OHIF این image در ریشه ساخته شده است؛ انتقال سادهٔ تمام فایل‌های آن به زیرپوشه نیازمند rebuild و تنظیم PUBLIC_URL است. زیردامنهٔ اختصاصی از تداخل مسیرهای سایت جلوگیری می‌کند.

درگاه DICOMweb به GET محدود است: QIDO مطالعه/سری/تصویر، metadata در سطح مطالعه/سری/تصویر، دریافت یک instance، frames، rendered همان instance و bulk همان instance. دریافت multipart همهٔ مطالعه یا سری و REST دلخواه آرشیو عمداً مسیر عمومی ندارند؛ تنها داده‌های ثبت‌شده و منتشرشده برای بیمار عبور می‌کنند.

اتصال مستقیم دستگاه با DICOM C-STORE، RIS/LIS، پرداخت، پیامک، چند مرکز و گزارش پزشک در این نسخه پیاده نشده‌اند. این نسخه فقط مسیر آپلود دستی اپراتور و مشاهدهٔ تصاویر بیمار را اجرا می‌کند.
