# بهره‌برداری و نگهداری

## اجزای مستقر

Nginx ورودی عمومی است. پرتال هویت، پرونده و انتشار را مدیریت می‌کند. Worker تنها پردازشگر صف است. Orthanc تصاویر را نگه می‌دارد؛ PostgreSQL دو دیتابیس جداگانهٔ `pacs_portal` و `orthanc` دارد. OHIF تصاویر را از درگاه مجاز پرتال می‌خواند. دسترسی بیمار به REST داخلی Orthanc وجود ندارد.

| داده | محل پایدار |
|---|---|
| کاربران، نشست، ارتباط پرونده و وضعیت انتشار | volume دیتابیس `postgres_data` |
| تصاویر DICOM اصلی | volume `orthanc_data` |
| فایل آپلود و فایل استخراج‌شدهٔ پردازش | volume `uploads` |
| رمزها، دامنه، گواهی TLS | `.env` و `deploy/tls/` روی میزبان |

نام واقعی volumeها پیشوند `patient-pacs_` دارد. دستور `docker compose down -v` داده‌ها را حذف می‌کند؛ برای توقف عادی از `stop` یا `down` بدون `-v` استفاده کنید. Worker را در این نسخه فقط با یک replica اجرا کنید. ساخت schema در نصب اول خودکار است؛ تغییر ساختار در ارتقای آینده به migration جدا نیاز دارد.

## وضعیت آپلود

`queued → processing → ready / needs_review / failed → published`

فایل‌ها ابتدا کامل اعتبارسنجی می‌شوند. خطای ارتباط آرشیو ممکن است بخشی از تصاویر را در آرشیو ذخیره کرده باشد؛ تلاش مجدد همان checksum و SOP UID را بررسی می‌کند و رکورد تکراری نمی‌سازد. کار متوقف‌شده در حالت processing بعد از ۱۰ دقیقه دوباره در صف قرار می‌گیرد. وضعیت انتشار در سطح تک‌تصویر است، نه فقط مطالعه.

فایل‌های موقت این نسخه خودکار حذف نمی‌شوند. ظرفیت staging را پایش کنید؛ برای حذف نسخهٔ موقت آپلود منتشرشده، پس از پشتیبان‌گیری از دستور `scripts/cleanup_staging.py` استفاده کنید. فایل‌های منتظر پردازش یا بررسی هویت حفظ می‌شوند. تصاویر اصلی آرشیو در این دستور حذف نمی‌شوند.

```bash
docker compose exec portal python -m scripts.cleanup_staging --days 30
# پس از بررسی تعداد:
docker compose exec portal python -m scripts.cleanup_staging --days 30 --apply
```

## پشتیبان رمزنگاری‌شده

ابزار `age` روی میزبان نصب شود. یک کلید خصوصی بسازید و خارج از سرور نگهداری کنید:

```bash
age-keygen -o /SAFE/OFFLINE/pacs-age.key
bash scripts/backup.sh --recipient age1YOUR_PUBLIC_KEY
```

پشتیبان هنگام توقف کوتاه ورودی، پرتال، Worker و Orthanc ساخته می‌شود تا snapshot فایل‌ها و هر دو دیتابیس با هم سازگار باشند. دیتابیس روشن می‌ماند. اسکریپت در پایان یا شکست، سرویس‌هایی را که از قبل روشن بودند دوباره راه می‌اندازد. کلید عمومی کافی است؛ کلید خصوصی برای پشتیبان‌گیری روی سرور لازم نیست.

خروجی شامل dump دو دیتابیس، فایل‌های آرشیو، staging، تنظیمات و گواهی‌ها است و با age رمز می‌شود. نسخهٔ رمزنگاری‌شده را روی مقصد مستقل کپی کنید و checksum آن را نگه دارید. داشتن فایل پشتیبان به‌تنهایی اثبات بازیابی نیست؛ بازیابی را روی سرور آزمایشی تمرین کنید.

## بازیابی

این دستور همهٔ داده‌های مقصد را جایگزین می‌کند و عمداً دو پرچم صریح می‌خواهد:

```bash
bash scripts/restore.sh --confirm /BACKUP/pacs-BACKUP.tar.gz.age \
  --identity /SAFE/pacs-age.key --replace-all-data
```

قبل از اجرا، `.env` و TLS مناسب مقصد آماده، image پرتال build و دیتابیس در حال اجرا باشند. اگر روی سرور تازه هستید، bundle را در مسیر خصوصی با age باز کنید، `config.env` را به `.env` منتقل و فقط دامنه/TLS را مطابق مقصد تنظیم کنید؛ رمزها را تغییر ندهید. سپس stack را راه‌اندازی و restore را اجرا کنید. کلید خصوصی را بعد از کار از سرور عملیاتی بردارید.

Restore ابتدا bundle را بررسی می‌کند، سرویس‌های نویسنده را متوقف، هر دو دیتابیس و volumeهای تصاویر/staging را بازیابی و همهٔ نشست‌های کاربران را باطل می‌کند. اگر مرحله‌ای شکست بخورد، سرویس‌های نویسنده خاموش می‌مانند؛ گزارش خطا را رفع و بازیابی را از ابتدا اجرا کنید. یک مطالعهٔ معلوم، تعداد تصاویر و ممنوع بودن حساب بیمار دوم را کنترل کنید.

## پایش عملیاتی

`/health` سلامت پاسخ پرتال و اتصال دیتابیس را نشان می‌دهد؛ تضمین سلامت آرشیو، Worker یا فضای دیسک نیست. این موارد را جدا پایش کنید:

- فضای آزاد volumeها و staging، حداقل ۲۰٪ فضای آزاد عملیاتی.
- آپلودهای queued/processing قدیمی و worker log.
- شکست پشتیبان‌گیری، فاصلهٔ آخرین نسخهٔ سالم و نتیجهٔ بازیابی تمرینی.
- انقضای گواهی، سرویس‌های Docker و مصرف RAM/CPU.

برآورد خام ذخیره‌سازی: تعداد مطالعهٔ روزانه × میانگین حجم × تعداد روز نگهداری؛ staging و پشتیبان مستقل را اضافه کنید. منابع به تعداد کاربران همزمان و نوع تصویر وابسته‌اند. فایل‌های واقعی دستگاه، سری‌های چندفریمی و syntaxهای فشرده را در پایلوت بررسی کنید.
