# گزارش تست تحویل ۱٫۰٫۰

تاریخ: ۶ اکتبر ۲۰۲۶. داده‌های آزمون فقط مصنوعی‌اند؛ فایل بیمار واقعی استفاده نشده است.

## تست‌های خودکار

**۷۹ تست پاس شدند**؛ این نتیجه در یک محیط Python 3.12 تازه، با نصب فقط `requirements-dev.lock` تکرار شد. بررسی Ruff و کامپایل فایل‌های Python نیز پاس شدند.

پوشش شامل ورود/خروج/انقضا، CSRF و مبدأ درخواست، محدودسازی ورود ناموفق، حساب و نقش، آپلود پایدار، بررسی هویت، انتشار صریح، بازیابی کار متوقف‌شده، تلاش مجدد، تکرار یکسان و تعارض SOP UID، تعارض Series UID، ZIP ناامن و سقف حجم، دادهٔ پیکسلی خراب، JPEG معتبر و خراب، RLE معتبر و محدودیت حجم بازشده است.

درگاه تصاویر برای مطالعات و متادیتا و frames و bulk آزموده شده است؛ بیمار دوم و تصویر تازهٔ تأییدنشده در مطالعهٔ منتشرشده اجازهٔ عبور ندارند. تست‌های بازیابی، رد bundle ناقص **قبل از دستور حذف دیتابیس** و خواندن بافر محدود و رد traversal/link را بررسی می‌کنند. جابه‌جایی فایل snapshot آزموده شد؛ تغییر مالک فایل در آزمون واحد شبیه‌سازی شده و فقط در کانتینر عملیاتی قابل تأیید نهایی است.

## اجزای واقعی

آرشیو از image رسمی `orthancteam/orthanc:26.7.0`، شامل Orthanc **1.12.11** و افزونهٔ DICOMweb **1.23** اجرا شد. دارایی‌های واقعی OHIF **3.11.0** و Nginx **1.28.3** نیز استفاده شدند. اجرا در محیط بومی ایزوله انجام شد؛ Docker daemon در محیط آزمون موجود نبود.

آزمون HTTP واقعی آپلود ZIP هشت تصویر، پردازش Worker، وضعیت ready، مخفی بودن قبل از انتشار، انتشار، QIDO/metadata، دریافت هر هشت frame، bulk URI مجاز، منع بیمار دوم، خروج و ابطال نشست را پاس کرد. REST آرشیو بدون احراز هویت پاسخ ۴۰۱ داد.

آزمون مرورگر با Playwright **1.62.1** و Chrome Headless Shell **154.0.8037.92**، ورود اپراتور، ساخت بیمار، آپلود، تأیید، ورود بیمار و نمایش OHIF و تغییر برش با چرخ ماوس را پاس کرد. **۸ درخواست frame موفق** و **۲۵۲ سطح رنگ** روی canvas تصویر ثبت شد؛ اندازهٔ viewport برابر **۸۵۵ × ۶۹۷** بود. خطای JavaScript و درخواست ناموفق مجاز DICOMweb ثبت نشد. صفحهٔ بیمار در عرض ۳۹۰ پیکسل نیز بررسی شد. تصاویر شاهد و خروجی JSON در `docs/test-evidence/` قرار دارند.

Docker Compose **2.40.3** هر دو فایل نصب محلی و HTTPS را parse کرد. Nginx تنظیمات TLS را با گواهی خودامضای آزمایشی به‌درستی پذیرفت. syntax اسکریپت‌های Bash بررسی شد.

## بازبینی مستقل و اصلاحات

یک بازبین مستقل کل پروژه را خواند. اشکالات زیر با تست بازتولید و اصلاح شدند:

- حفظ Host عمومی در subrequest احراز هویت و health؛ رفع شکست نمایشگر پشت Nginx.
- توقف بازیابی روی bundle ناقص و پیش‌بررسی dumpها/snapshot قبل از تغییر دیتابیس.
- بررسی bundle به‌صورت stream، بدون بارگذاری کل پشتیبان در RAM.
- رمزگشایی و کنترل اندازهٔ فریم فشرده قبل از پذیرفتن فایل.
- رد SeriesInstanceUID مشترک بین دو مطالعهٔ یک batch.
- حفظ فاصله‌های ابتدا/انتهای گذرواژه مطابق ابزار مدیریت حساب.

تست واقعی همچنین نیاز image OHIF به دارایی‌های gzip را نشان داد. تنظیم Nginx اختصاصی، درگاه داخلی صریح و استثنای config غیر‌فشرده اضافه شد؛ entrypoint دیگر فایل bind شدهٔ config را تغییر نمی‌دهد.

## موارد اجرا‌نشده

- ساخت و اجرای کامل Docker Compose با PostgreSQL و volumeهای واقعی؛ parse تنظیمات، جای اجرای کامل را نمی‌گیرد.
- اجرای کامل پشتیبان‌گیری age و بازیابی PostgreSQL/مالکیت فایل روی سرور؛ پیش‌بررسی و منطق فایل‌ها آزموده شده‌اند.
- دامنه و گواهی عمومی واقعی، اتصال به سایت موجود و ورود مشترک.
- آزمون بار بزرگ، خروجی همهٔ دستگاه‌ها و همهٔ transfer syntaxها، مرورگرهای دیگر و اعتبارسنجی نمایش تشخیصی.

فایل فشرده‌ای که decoder نصب‌شده نتواند باز کند، رد می‌شود و قابل انتشار نیست. JPEG/JPEG2000/RLE decoderها در وابستگی‌ها هستند؛ آزمون مثبت این تحویل JPEG Baseline و RLE را پوشش می‌دهد.

تست‌های پاس‌شده و اصلاح اشکالات، تضمین ریاضی «صفر باگ» نیستند. پیش از استفادهٔ عمومی، اجرای بسته، بازیابی تمرینی و تصاویر دستگاه‌های مرکز باید روی سرور نهایی تأیید شوند.

## تکرار آزمون زنده

فقط در یک **نسخهٔ آزمایشی مستقل با دیتابیس خالی** و آدرس loopback، fixture بسازید. تست‌ها حساب‌های مصنوعی می‌سازند و تصویر نمونه منتشر می‌کنند؛ روی دادهٔ عملیاتی اجرا نشوند.

```bash
# در نسخهٔ مستقل تست؛ گذرواژهٔ تست را خودتان انتخاب کنید.
export PACS_TEST_PASSWORD='YOUR_TEST_PASSWORD_AT_LEAST_12_CHARS'
docker compose cp tests portal:/app/tests
docker compose exec -e PACS_TEST_PASSWORD portal \
  python -m tests.live_seed --confirm-empty-test-db
export PACS_TEST_URL=http://127.0.0.1:8080
npm ci
npx playwright install chromium
npm run test:browser
```

آزمون HTTP جایگزین از محیط توسعه با `python tests/live_http.py` قابل اجراست؛ آن و آزمون مرورگر هرکدام fixture تازه می‌خواهند، چون تصاویر را منتشر می‌کنند. `CHROMIUM_EXECUTABLE` برای مسیر مرورگر موجود و `PACS_TEST_ARTIFACTS` برای مقصد شواهد اختیاری‌اند. `PACS_TEST_ARCHIVE_URL` فقط در آزمون بومی خصوصی برای بررسی ۴۰۱ آرشیو استفاده می‌شود؛ آرشیو را برای اجرای تست روی اینترنت منتشر نکنید.
